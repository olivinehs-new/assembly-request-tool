# 자료요구서 문항 분리

원문 자료요구서 PDF를 문항 단위로 나누는 `split.py`를 프로젝트 폴더 맨 위에 만들고, 그 코드로 `data/문항목록.csv`를 생성한다.

## 준비

1. 프로젝트의 `AGENTS.md`, `CONTEXT.md`, `PROGRESS.md`와 `처리지침.md` 제2장을 먼저 읽는다.
2. `pypdf` 설치 여부를 확인한다. 설치되어 있지 않으면 `pip install pypdf` 명령을 사용자에게 보여 주고, 허락을 받은 뒤에만 설치한다.
3. `원문/*.pdf`, 기존 `split.py`, `data/문항목록.csv`를 확인한다.
4. 사용자가 교체한 `data/문항목록.csv`가 있으면 정답 예시로 보존하며 덮어쓰거나 수정하지 않는다.

## 코드와 파일 조건

- PDF 처리에는 `pypdf`만 사용한다. `csv`, `re`, `pathlib` 등 파이썬 표준 라이브러리는 사용할 수 있다.
- 실행 코드는 프로젝트 폴더 맨 위의 `split.py` 하나로 만든다.
- 원문 PDF와 `data` 폴더의 기존 파일은 수정하지 않는다.
- 새 CSV를 만들 때는 사용자가 지정한 새 경로를 사용하고, 기존 파일이 있으면 임의로 덮어쓰지 않는다.
- CSV는 `utf-8-sig`, `newline=""`로 작성한다.
- 열과 순서는 다음과 같다.

`파일명 | 위원회 | 의원 | 제출기한 | 문항번호 | 요구내용 | 세부항목 | 비고`

## 문항 추출 규칙

1. 첫 줄 `○○위원회 ○○ 의원실 자료요구서`에서 위원회와 의원을 추출한다.
2. `수신: … 제출기한: YYYY. M. D.(요일) HH:MM까지` 줄에서 날짜를 추출해 `YYYY-MM-DD`로 저장한다.
3. `수신:`, `담당 보좌관:`, `끝.` 줄은 문항에 넣지 않는다. 이름과 연락처도 저장하지 않는다.
4. 줄 맨 앞이 `숫자.`이면 새 문항으로 시작한다.
5. `가.`, `나.` 등은 앞 문항의 세부항목으로 저장한다. 항목 표시는 유지하고 여러 항목은 한 셀에서 ` / `로 연결한다.
6. `※`로 시작하는 줄은 앞 문항의 비고로 저장한다. CSV에는 `※`와 그 뒤 공백을 제외한 내용만 넣고, 여러 비고는 ` / `로 연결한다.
7. 그 밖의 줄은 바로 앞에서 처리한 요구내용·세부항목·비고에 공백 한 칸으로 이어 붙인다.
8. 모든 페이지의 줄을 순서대로 연결한 뒤 처리한다. 다음 페이지 첫 줄의 세부항목이나 비고가 앞 페이지 마지막 문항에 붙는 경우를 보존한다.

## 교체된 문항목록에 맞추기

교체된 `data/문항목록.csv`가 있으면 `split.py`의 파싱 결과를 메모리에서 만들고 기준 CSV와 비교한다. 기준 CSV는 실행 결과로 덮어쓰지 않는다.

다음 항목이 모두 같아야 한다.

- 열 이름과 열 순서
- 전체 행 수와 파일별 행 수
- 행의 순서
- 모든 셀의 문자열 값
- 세부항목의 ` / ` 구분 방식
- 비고에서 `※`가 제거된 방식
- UTF-8 BOM 여부

다른 셀이 하나라도 있으면 차이가 난 열과 행을 찾아 `split.py`를 고친 뒤 다시 비교한다. 행 수만 같다고 완료하지 않는다.

## 확인

파일별로 다음 표를 제시한다.

`파일명 | 파일명의 문항 수 | 뽑은 문항 수 | 마지막 번호 | 번호 연속 | 일치(O/X)`

- 파일명의 `NN문항`과 추출한 문항 수가 같은지 확인한다.
- 첫 번호부터 마지막 번호까지 빠짐없이 연속인지 확인한다.
- `파일명의 문항 수 = 뽑은 문항 수 = 마지막 번호`이고 번호가 연속일 때만 일치를 O로 표시한다.
- 일치가 X이면 원인을 찾아 코드를 고치고 다시 실행한다.
- 세부항목과 비고가 모두 있는 문항 3개를 골라 원문 PDF 내용과 CSV 결과를 나란히 제시한다.
- CSV 전체에서 보좌관 이름, 연락처, `담당 보좌관`, `수신:`이 저장되지 않았는지 확인한다.
- 교체된 기준 CSV가 있으면 모든 셀의 차이가 0건인지 함께 보고한다.

작업이 끝나면 만든 파일, 확인 결과, 남은 문제를 `PROGRESS.md`에 기록한다.
